## 들어가기에 앞서

요즘 제가 하는 일 중 반복되는 부분은 **Claude Code 스킬** 쪽에 하나씩 옮겨 두고 있습니다.

한 번 정리해 두면 다음부터는 텔레그램이나 터미널에 **슬래시 커맨드 한 줄**만 치면 알아서 돌아가도록 만든 구조입니다.

---

## 지금 굴리고 있는 것들

| 영역 | 스킬 | 자동화한 지점 |
|------|-------|--------------|
| **PR 기반 git-flow** | `/feat`, `/finish-feat`, `/start-rc`, `/rc-fix`, `/release`, `/hotfix` | 브랜치 생성, PR 생성, 버전 태그 증가, `package.json` 버전 맞추기 |
| **Jira → PR 흐름** | `/feat {issue-key}` + PR 템플릿 감지 | 이슈 키로 브랜치 이름, 커밋 로그 기반 PR 본문, 레포별 템플릿 자동 채움 |
| **주간보고** | `/weekly-report` | Jira 이슈 조회·분류 + 연결된 PR로 한 줄 요약 → Google Sheets 작성 |
| **README / 구조 문서** | `sync-readme` 훅 | 코드 변경 감지 시 "업데이트 필요" 신호만 남기고 실제 반영은 작업 마무리 타이밍에 |

---

## 최근 드는 생각

예전에는 **엑셀·파워포인트 같은 오피스 도구를 잘 다루는 사람**이 일의 속도에서 한 발 앞서 나갔습니다.

지금은 같은 자리를 **AI를 도구로 잘 다루는 사람**이 차지하고 있는 것 같습니다.

단순히 "AI한테 시켰다"가 아니라,

- 반복 작업을 **스킬 / 커맨드 / 훅** 같은 단위로 잘라 두고
- **사람의 판단**과 **기계의 절차**를 나누고
- **어디에 신호를 남기고 어디서 실제 작업을 할지**를 흐름으로 설계하는 쪽,

이런 감각이 앞으로 일의 속도 차이를 만든다고 봅니다.

엑셀 단축키가 **개인의 손놀림**을 빠르게 했다면, AI 자동화는 **작업 흐름 자체를 시스템으로 굳혀 두는 쪽**에 가깝습니다.
