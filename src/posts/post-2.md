## 들어가기에 앞서

Node.js 백엔드 개발자로 입사한 지 10개월이 지났습니다.

인턴 회고를 먼저 쓰고 싶었지만 개인 블로그 세팅이 늦어져 이제야 첫 회고를 남깁니다.

아직은 많이 부족하지만, 지난 10개월을 돌아보며 **잘한 점**, **아쉬운 점**, 그리고 **앞으로의 방향**을 정리해보려고 합니다.

---

## Keep (잘한 점)

### 1. 기록하는 습관

가장 잘했다고 생각하는 점은 **기록하는 습관**입니다.

회사에서 배운 내용이나 해결했던 문제는 대부분 옵시디언에 정리해왔습니다. 덕분에 언제든 다시 찾아볼 수 있는 저만의 지식 저장소가 만들어졌습니다.

입사 전부터 옵시디언을 개인 기록 용도로 써왔는데, 운 좋게도 회사에서 열린 개발자 컨퍼런스에서 옵시디언을 주제로 발표할 기회까지 얻었습니다. 예전보다 나아진 발표 실력을 체감할 수 있어 개인적으로 의미 있는 경험이었습니다.

### 2. 실무에서의 문제 해결 경험, 배운 점

10개월 동안 단순 유지보수보다는 **실제 서비스에서 발생하는 문제를 직접 경험하고 해결**해볼 수 있었습니다.

- 데이터 정합성 오류 감지 배치 프로그램 개발
- N+1 문제 해결
- Race Condition 문제 해결 및 트랜잭션 도입
- 쿼리 최적화
- 사용자 세션 만료 문제 해결 (STOMP 기반 큐)
- Docker 이미지 최적화 (5GB → 1.7GB)
- 레거시 프로젝트 마이그레이션
- 로그의 중요성 인지

---

## Problem (아쉬운 점)

**코드 흐름을 빠르게 파악하는 능력**이 아직 부족하다고 느꼈습니다.

오류가 났을 때 원인을 찾는 데 시간이 많이 걸렸고, 그만큼 업무 효율이 떨어졌습니다.

기능을 개발할 때 **다양한 예외 케이스를 미리 충분히 고려하지 못한 점**도 아쉬웠습니다.

도메인 지식과 시스템 구조에 대한 이해가 아직 완전하지 않은 탓도 있겠지만, 무엇보다 깊이 고민하지 않은 채 개발을 진행한 경우가 있었다는 걸 스스로 깨달았습니다.

---

## Try (앞으로 시도할 것)

앞으로는 단순 유지보수보다 **API 기능 개발과 설계 단계부터 참여**하면서 시스템 구조를 더 깊이 이해하고 싶습니다.

지금 프로젝트에는 벨리데이션이 충분히 적용돼 있지 않아 크고 작은 문제가 자주 생기는데,

- 공통 벨리데이션 로직 추가
- 테스트 코드 도입

으로 **조금 더 안전하고 예측 가능한 프로젝트**로 다듬어가고 싶습니다.

---

아직 배워야 할 것이 훨씬 많지만, 지난 10개월은 "실제 서비스에서 문제가 어떻게 발생하고, 어떻게 해결할 수 있는지"를 몸으로 배운 시간이었다고 생각합니다. 다음 회고에서는 조금 더 성장한 모습으로 글을 남길 수 있기를 기대합니다!!
